Build the dataset that the question actually requires

Capability. Construct a research dataset whose measurement, linkage, coverage and permitted use can be defended. The prerequisite is theory building and model discipline: a model's variable is not automatically a field in an administrative file. Use the target and counterfactual distinctions from question design, and the version discipline from reproduction. All records and study decisions below are original fictional teaching material. They contain no actual borrowers and authorize no real collection.

A bank's accounting system records what the bank needs to administer contracts. A research question may concern a borrower's total financing, the affordability of repayment or access to credit. Those objects differ. Even flawless code cannot turn a partial lender file into a complete credit history, or a self-reported late payment into a direct observation of every dimension of financial distress. Data construction is part of the argument connecting the economic concept to the reported result.

1. Specify measurement, collection and access together

Start with a measurement contract: target population; unit of observation; reference date or interval; economic concept; operational variable; units; source coverage; and missingness states. Define the grain, meaning what one row represents, and a key that distinguishes those rows. A loan-date table and a borrower-date table have different grains. Aggregating changes the grain; a join can multiply rows without creating new loans. Reconcile counts and monetary totals at each step.

A proxy is an observed measure used to learn about a concept that is not directly observed. Explain the mapping and its possible failures. A loan stock is not the flow of new advances: repayments, write-offs, sales and valuation changes can move the stock. Bank credit is not all financing if nonbank lenders are absent. A missed-payment report may reflect misunderstanding, recall or reporting incentives. Validate definitions against source documentation, transaction examples and, where permitted, independent measurements. Agreement between two files copied from the same source is not independent validation.

A collection plan specifies who produces each field, when, under which definitions, and how changes will be recorded. Before acquiring real records, establish the applicable access authority, permitted purpose, retention conditions and disclosure procedure. A researcher's ability to download a file does not determine the permitted use of its contents. For primary collection, pilot whether participants understand the questions and whether the recording process captures the intended event. For administrative data, inspect the institution's recording incentives and changes in its systems.

The AEA data and code policy inspected in Chapter 3 supplies a bounded professional reference for documenting provenance, transformations and the connection between code and outputs. Preserve raw snapshots and a transformation log. A hash identifies bytes; a dictionary explains their meaning. Neither establishes permission or factual accuracy by itself.

Record missingness separately from values. Useful states include observed amount, verified zero, missing report, unresolved linkage, outside the defined population and not applicable. Their consequences differ. A missing row can mean zero only if the recording contract and coverage establish that all relevant events would have been recorded. An absent institution's feed cannot supply that assurance. Retain reasons and denominators rather than collapsing all states to an empty cell.

2. Link entities without manufacturing observations

A crosswalk maps source identifiers to research entities. Names are evidence for a match, not necessarily identifiers. Record the source, effective dates and evidence behind a mapping. If an account code is reused or an entity merges, a timeless crosswalk can join the wrong units. Define whether a merger changes the target entity or is mapped into a stable perimeter. Do not let an automatic nearest-name rule silently settle an ambiguous economic identity.

Distinguish exact duplicate deliveries from conflicting records and legitimate repeated observations. An identical retransmission may be removed under a documented rule, retaining its audit count. Two different amounts for the same loan and date need a version or adjudication rule; keeping whichever row happens to come last is not a substantive resolution. Two different loans held by the same borrower should be summed, not deduplicated by borrower name. Test uniqueness at the original grain before changing that grain.

Executable construction. The complete program below embeds the exact raw rows, accepted crosswalk and coverage record. Copy it into construct.py and run python3 -I -B construct.py. It uses standard-library exact fractions, performs no file or network access, and prints the analysis panel and audit fields. It deliberately refuses ambiguous mappings, conflicting duplicates and a missing amount labeled complete. The program can enforce the supplied metadata; it cannot verify that an actual provider told the truth.

from fractions import Fraction as F
import json

RAW = (
    ("L1", 0, "N", "n1", "thousand", 100),
    ("L2", 0, "S", "s7", "currency", 40000),
    ("L3", 0, "N", "n2", "thousand", 80),
    ("L1", 1, "N", "n1", "thousand", 90),
    ("L2", 1, "S", "s7", "currency", 60000),
    ("L4", 1, "S", "s9", "thousand", 20),
    ("L1", 1, "N", "n1", "thousand", 90),
    ("L3", 1, "N", "n2", "thousand", None),
)
LINKS = (("N", "n1", "B1"), ("S", "s7", "B1"),
         ("N", "n2", "B2"), ("S", "s9", "B3"))
COVERAGE = {(b, t): not (b == "B2" and t == 1)
            for b in ("B1", "B2", "B3") for t in (0, 1)}
ROSTER = ("B1", "B2")

def construct(rows, links, coverage, roster):
    mapping = {}
    for lender, account, borrower in links:
        if not all(type(x) is str and x for x in (lender, account, borrower)):
            raise ValueError("nonempty identifiers required")
        if (lender, account) in mapping:
            raise ValueError("crosswalk key is not unique")
        mapping[lender, account] = borrower
    borrowers = set(mapping.values())
    slots = {(b, t) for b in borrowers for t in (0, 1)}
    if set(coverage) != slots or any(type(v) is not bool for v in coverage.values()):
        raise ValueError("complete boolean coverage map required")
    if not roster or len(set(roster)) != len(roster) or not set(roster) <= borrowers:
        raise ValueError("unique known target roster required")
    totals = {k: F(0) for k in slots}
    seen, duplicates = {}, 0
    for row in rows:
        if not isinstance(row, (tuple, list)) or len(row) != 6:
            raise ValueError("six fields per row required")
        loan, date, lender, account, unit, amount = row
        if not all(type(x) is str and x for x in (loan, lender, account)):
            raise ValueError("invalid record identifier")
        if type(date) is not int or date not in (0, 1):
            raise ValueError("date outside contract")
        if type(unit) is not str or unit not in ("currency", "thousand"):
            raise ValueError("unknown unit")
        if amount is not None and (type(amount) is not int or amount < 0):
            raise ValueError("nonnegative integer or None required")
        if (lender, account) not in mapping:
            raise ValueError("unresolved account linkage")
        key = (lender, loan, date)
        if key in seen:
            if seen[key] != tuple(row):
                raise ValueError("conflicting loan-date records")
            duplicates += 1
            continue
        seen[key] = tuple(row)
        slot = (mapping[lender, account], date)
        if amount is None:
            if coverage[slot]:
                raise ValueError("missing balance cannot be complete")
        else:
            totals[slot] += F(amount, 1000 if unit == "currency" else 1)
    panel = [[b, t, str(totals[b, t]) if coverage[b, t] else None,
              "complete" if coverage[b, t] else "missing"]
             for b, t in sorted(slots)]
    return {"baseline": list(roster), "duplicates_removed": duplicates,
            "panel": panel, "unique_loan_dates": len(seen)}

if __name__ == "__main__":
    print(json.dumps(construct(RAW, LINKS, COVERAGE, ROSTER), sort_keys=True))

3. Treat access, consent and disclosure as design questions

Privacy concerns what information about people or organizations can be exposed and used. Confidentiality concerns how entrusted information is handled. Replacing a name with a code does not necessarily remove the ability to connect a row to its subject. Linkage keys and rare attribute combinations may remain informative. The abstract of NIST SP800-188 (2023) emphasizes evaluating disclosure risk and choosing a sharing model; it warns that masking personal information alone may be insufficient. This is a bounded reference to that abstract, not a claim to have implemented its full technical guidance.

The 1979 Belmont Report provides an ethical framework of respect for persons, beneficence and justice. Its consent discussion distinguishes information, understanding and voluntary choice. Applied here, consent is a process to evaluate, not merely a signature field. These principles do not determine every current legal or institutional requirement. For an actual project, obtain the applicable determination about review, access and consent arrangements before using records; neither a lender's cooperation nor this chapter supplies it.

Minimize the information needed for the question. Separate linkage material from analysis variables, define who can access each, and specify the permitted outputs and retention end point. A deletion promise must be compatible with the actual research and archive arrangements; do not promise withdrawal from an already published aggregate if that cannot be implemented. Access to administrative data and agreement to answer a survey are distinct matters. State whether linkage is proposed and what declining would mean.

Research integrity also concerns the analysis record. Preserve exclusions, match adjudications, definition changes and unexplained discrepancies. Correct errors visibly, identifying affected outputs. Do not fabricate an unobserved outcome, silently change a target to improve a result, or describe an unperformed check as completed. An unresolved conflict can justify postponing analysis or narrowing the claim. It need not be concealed to preserve a useful project.

Completed missingness analysis. The response rate among those who agreed is 4/5. The observed late-payment fraction is 3/8. For the60 consenting borrowers, the12 missing indicators may each be0 or1. The fraction is therefore between18/60 and30/60: (3/10,1/2). For the100 eligible borrowers,52 indicators are unobserved; the compatible fraction is between18/100 and70/100: (9/50,7/10). They do not establish true hardship rates, sampling confidence coverage or a causal effect. The binary measurement definition itself requires scrutiny.

The bounds are sharp under only the stated binary restriction: setting every unobserved indicator to0 attains the lower endpoint, and setting every one to1 attains the upper endpoint. Every integer count between is attainable, so the feasible rates form a finite grid within each displayed interval; no claim that arbitrary real-valued rates between grid points occur in a fixed finite roster is needed. The complete-case fraction3/8 need not equal either target fraction. More accurate arithmetic does not resolve nonresponse or consent selection.

Complete solutions and evaluation criteria

1. Define what a row and zero mean

Source grain is loan-date within lender, keyed by(lender,loan,date); analysis grain is borrower-date, keyed by(borrower,date). The fixed target roster is B1,B2; credit includes N and S only; the balance unit is thousands of the same currency at dates0 and1. An observed zero requires reliable coverage and evidence of no balance. B2's incomplete date1 remains unknown, whereas B3's complete empty date0 inventory establishes zero. Balances alone do not measure new advances, credit supply effects, total finance across excluded lenders, investment or welfare. Full credit supplies every requested contract component and two explicit limits, rather than a generic statement that data may be imperfect.

2. Diagnose two different multiplications

Keeping the retransmission adds90 to B1's correct150, yielding240; with initial140 its growth is (240,5/7). The duplicated crosswalk instead doubles the N component at both dates after raw deduplication: initial2(100)+40=240 and final2(90)+60=240, giving (240,240,0). The first repeats a delivered observation; the second repeats matches during a join. No borrower acquired another loan because a row appeared twice. Check the key and reconcile totals at both stages; deduplicating only the final borrower table would discard legitimate loans or fail to recover the correct sums.

3. Preserve the unknown component

Baseline initial credit is220 and final credit150+x, so growth=(x−70)/220. Its sharp continuous-balance interval is (-7/22,9/22), with endpoints at x=0 and160. If raw balances are restricted to integer currency units, feasible rates instead lie on the corresponding fine grid with the same endpoints. Choosing x=0 yields−7/22; choosing x=100 yields3/22, so opposite aggregate signs fit the observed B1 growth. Every allowed x preserves the known records, making the bound constructive. The interval is conditional on the extra upper bound, not a confidence interval or a consequence of the program.

4. Distinguish evidence from imputation

In a new documented vintage, change B2's date1 amount to0 and its coverage flag to complete, retaining the old inputs. The panel then reports observed zero. Baseline final credit150 gives growth -7/22. If only the amount is changed while coverage remains incomplete, the program still reports a missing borrower total: another unobserved loan could exist within the declared universe. The new closed-loan and coverage evidence—not the numeric substitution—justifies zero. Record provider/version/date, affected fields, evidence, old/new output and tests; do not erase the earlier missing-data result.

5. Update each denominator separately

The response rate is50/60=5/6; the observed rate is 19/50. Consenting borrowers have10 unobserved outcomes, so the possible positive counts are every integer19 through29, giving (19/60,29/60). Eligible borrowers have50 unobserved outcomes, so counts run through69 and the bounds are (19/100,69/100). These are sharp logical count ranges given the binary definition, not probability statements or coverage-calibrated intervals. Neither the increased response rate nor a narrower bound proves that late payment captures all hardship.

5. Teach-back and delayed retention

Teach-back. Explain why a dataset can have unique keys and no code errors yet fail the economic question or ethical access contract. Use one measurement example and one access or disclosure example from this chapter.

Answer guide

A perfectly keyed N/S loan panel remains incomplete for total financing outside those lenders; a missing B2 total cannot become observed through a clean join. Separately, coded survey rows may remain linkable through rare attributes, and a functioning linkage program does not establish permitted use. Correct computation, appropriate measurement and authorized handling require separate evidence.

Delayed retention. A week later, a provider supplies a new crosswalk and asks you to overwrite the old one. Design a response that preserves reproducibility and tests whether the target population or measurements change.

Criteria and illustrative response

Preserve both versions, document the source/date/reason and effective periods, compare changed mappings, test key uniqueness and unresolved links, and rebuild the same frozen raw snapshot under each mapping. Reconcile borrower counts and balances and inspect whether a merger, corrected identity or reused code changes the target perimeter. Record affected outputs and justify any revised population. Verify permitted handling of both crosswalks; do not publish identifying material merely to show the comparison. A new hash alone does not explain what the mapping changes mean.
